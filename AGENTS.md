# devkit-skills: notes for agents

This repo is a Claude Code plugin marketplace of agent skills. There is no application code.

## Map

- `.claude-plugin/marketplace.json`: Claude Code marketplace. Also read by `npx skills`.
- `.agents/plugins/marketplace.json`: Codex marketplace (own plugins only).
- `skills.sh.json`: skills.sh groupings and paths.
- `plugins/<plugin>/skills/<skill>/SKILL.md` (+ `references/`): own skills.
- Third-party plugins (`angular`, `react`, `nextjs`, `spring-boot-community`) are referenced by source in `marketplace.json`, never copied here.
- `templates/SKILL.template.md`: starting point for a new skill. `templates/nextjs/AGENTS.md`: block generated by `next dev`.
- `scripts/validate_skills.py`, `scripts/check_version_bump.py`: CI checks.

## Rules

- Skill `name` equals its directory name, kebab-case, unique across the repo.
- `description` says what the skill does and contains "Use when"; mention siblings for "Not for".
- Frontmatter keys: `name`, `description`, `license: MIT`, `metadata.author: baibesh/devkit-skills`. Avoid Claude-only keys.
- SKILL.md body: aim for 250 lines, 500 max. Details go to `references/*.md` (400 lines max, one level deep, relative links).
- Every skill states its version targets and tells the agent to detect the project's real versions first.
- Do not duplicate upstream framework skills; refer to them by name.
- Any change under `plugins/<p>/` bumps `version` in both `plugins/<p>/.claude-plugin/plugin.json` and `.codex-plugin/plugin.json`, plus a `CHANGELOG.md` entry.
- New skill: add it to the plugin's `skills` array in `.claude-plugin/marketplace.json` and to `skills.sh.json` groupings.
- No `CLAUDE.md`, `package.json` or `bin/` inside plugin directories.
- English only. Conventional Commits.

Before finishing, run:

```sh
python3 scripts/validate_skills.py
claude plugin validate --strict .
for d in plugins/*/; do claude plugin validate --strict "$d"; done
```
